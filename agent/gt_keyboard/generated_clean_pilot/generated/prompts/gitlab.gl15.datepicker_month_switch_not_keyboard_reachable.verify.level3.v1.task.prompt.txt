Task: Inspect keyboard behavior within Keyboard assessment scope 1.1, 1.2, 1.3, 1.4, and 1.6 on this page.

WCAG criteria:
1.1 Keyboard navigation -> WCAG 2.1.1 Keyboard: All functionality of the content is operable through a keyboard interface without requiring specific timings for individual keystrokes, except where the underlying function requires input that depends on the path of the user's movement and not just the endpoints.
1.2 No keyboard traps -> WCAG 2.1.2 No Keyboard Trap: If keyboard focus can be moved to a component of the page using a keyboard interface, then focus can be moved away from that component using only a keyboard interface, and, if it requires more than unmodified arrow or tab keys or other standard exit methods, the user is advised of the method for moving focus away.
1.3 On focus -> WCAG 3.2.1 On Focus: When any user interface component receives focus, it does not initiate a change of context.
1.4 On input -> WCAG 3.2.2 On Input: Changing the setting of any user interface component does not automatically cause a change of context unless the user has been advised of the behavior before using the component.
1.6 Character key shortcuts -> WCAG 2.1.4 Character Key Shortcuts: If a keyboard shortcut is implemented in content using only letter (including upper- and lower-case letters), punctuation, number, or symbol characters, then at least one of the following is true: a mechanism is available to turn the shortcut off; a mechanism is available to remap the shortcut to use one or more non-printable keyboard characters; or the keyboard shortcut for a user interface component is only active when that component has focus.

Open the Expiration date datepicker by activating the #personal_access_token_expires_at field before inspecting the month navigation buttons.

Report an issue for each keyboard target or interaction where either 1.1 applies: the specified target or control cannot be reached by keyboard navigation, cannot be operated with its expected keyboard interaction once reached, or disrupts the expected keyboard path for reaching downstream controls; or 1.2 applies: keyboard focus can move into the target component or region but cannot move away using only expected keyboard interaction, or the page does not advise the required nonstandard exit method; or 1.3 applies: the target component receives focus and initiates a change of context without prior user advice and without explicit activation; or 1.4 applies: changing the target control value or selection automatically causes a change of context without prior user advice and without a separate confirmation step; or 1.6 applies: a single printable-character shortcut is active when focus is outside an editable target, and the shortcut cannot be turned off, remapped, or limited to focus on the target.

Verify keyboard behavior by navigating to and operating the same target or control through observed Tab, Shift+Tab, arrow-key, Enter, Space, Escape, or character-key interaction as relevant. Pointer interaction may be used only to reveal or cross-check the target, not as proof that the target or control itself is keyboard reachable or operable. Do not rely on source-code inspection alone.

Report only issues that are present. If no issues are present, use verdict `no_issue_found` and leave the `issues` list empty.
