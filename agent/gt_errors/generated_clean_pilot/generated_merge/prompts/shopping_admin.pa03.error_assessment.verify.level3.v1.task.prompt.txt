Task: Inspect error handling and status-message behavior within ERROR assessment scope E.1-E.4 on the My Account page.

WCAG criteria:
E.1 Error Identification -> WCAG 3.3.1 Error Identification: If an input error is automatically detected, the item that is in error is identified and the error is described to the user in text.
E.2 Error Suggestion -> WCAG 3.3.3 Error Suggestion: If an input error is automatically detected and suggestions for correction are known, then the suggestions are provided to the user, unless it would jeopardize the security or purpose of the content.
E.3 Error Prevention -> WCAG 3.3.4 Error Prevention (Legal, Financial, Data): If submitting data might have serious consequences, users must be able to correct the data input before finalizing a submission. If the page allows users to make legal commitments or financial transactions, modify or delete data in a data storage system, or submit test responses, at least one of the following must be true: submissions are reversible; data entered by the user is checked for input errors, and the user is given an opportunity to correct them; or the user can review, confirm, and correct information before finalizing the submission.
E.4 Status Messages -> WCAG 4.1.3 Status Messages: In content implemented using markup languages, status messages can be programmatically determined through role or properties such that they can be presented to the user by assistive technologies without receiving focus.

Report an issue for each target interaction, input-error path, or serious-consequence submission path where either E.1 applies: the target path has an automatically detected input error and the page does not identify the item that is in error or describe the error to the user; or E.2 applies: the target path has an automatically detected input error and the page does not provide an actionable correction suggestion; or E.3 applies: the target submission allows users to make legal commitments or financial transactions, modify or delete data in a data storage system, or submit test responses, but does not provide a reversible submission, input-error checking with an opportunity to correct, or a review/confirm/correct step before finalizing the submission; or E.4 applies: the target interaction triggers an active same-page status message and that message is not programmatically exposed through role, aria-live, or equivalent status-message semantics.

Do not report the rendered status/error/progress message node, or the submit button when the issue belongs to a field/control.

Report only issues that are present. If no issues are present, use verdict `no_issue_found` and leave the `issues` list empty.
